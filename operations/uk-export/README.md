# UK export website operating kit

Status: prepared, not sent. Public changes are not deployed. Start with Shibiao; do not build further unsolicited demos until this test has run.

## Workflow
1. QA the public offer and demo on desktop and phone. Use screenshots only as unofficial concepts, not endorsements.
2. Deploy approved site changes. Check HTTPS, demo, proposal and email links on the public domain.
3. Send a personal test email; check reply routing, signature and authentication headers. Do not infer delivery from an SMTP success alone.
4. Verify recipient is a relevant corporate business contact, its country and applicable marketing rules. Public addresses are not blanket consent. UK PECR corporate-subscriber rules differ from sole traders/partnerships; named work contacts can still involve personal data. Overseas rules may differ. Keep a legitimate-interests assessment where applicable. Never use employer-confidential data or imply buying interest. Do not contact if permission/eligibility is uncertain.
5. Send ONE manually reviewed message using templates/outreach.md. Record it in prospects.csv. No tracking pixels, purchased lists or bulk automation.
6. At most one follow-up after 7–10 days; none after objection or opt-out. Record suppression and check before future contact. Delete unnecessary prospect personal data after 90 days without engagement; retain only minimum suppression information needed to honour objections.
7. Interested reply: use discovery questions, then send a completed scope/acceptance email and invoice. No build until written acceptance and cleared deposit.
8. Build in client-owned hosting/domain accounts; request collaborator invitations, never passwords by email. Review factual claims and rights to materials.
9. Two consolidated revision rounds. Written approval, final invoice, cleared payment, then custom-domain launch and handover.
10. Test enquiries end-to-end using approved providers and privacy disclosures. Begin 14-day defect correction window. Offer care only if useful.

## Success test
Send one researched message, one optional follow-up, and log replies, qualified discussions and paid deposits. A click is not a sale. After 3–5 relevant prospects, reassess offer/message before investing in more demo production. Do not lower prices automatically in response to silence.

## File guide
- `templates/outreach.md`: first email, follow-up and interested reply.
- `templates/contact-assessment.md`: contact eligibility/privacy decision record.
- `templates/agreement-and-invoices.md`: written scope, acceptance and invoice setup.
- `templates/onboarding-and-handover.md`: content request, build/launch checks and client emails.
- `templates/care-plan.md`: optional recurring service agreement.
- `prospects.csv`: starter template only; copy into `private/` or your private spreadsheet before adding personal/customer data. Never commit real contact history, objections or invoices.
- `QA.md`: actual checks completed and outstanding gates.
- Public `uk-export-terms.html`: customer-facing scope linked from proposal/general policies.

Production hosting excludes `operations/` and `scripts/` via GitHub Pages `_config.yml`. This is not access control: repository files may still be public on GitHub, so never store confidential data here.
